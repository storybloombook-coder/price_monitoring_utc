# Price Monitor 5.0.2 — инструкция

## Исправления 5.0.2

`Smartech Shop` на Hinnavaatlus теперь распознаётся как магазин Smartech.ee и попадает в столбец Smartech. Исправление применяется также к старым и кешированным результатам при открытии прогона: повторный запрос цены не нужен. Цена, время проверки и исходное имя продавца не меняются. Для одноимённых продавцов в других странах сохраняются ограничения сопоставления.

## Исправления 5.0.1

- Повторный запуск EXE открывает страницу уже работающего приложения. При отказе обычного открытия браузера используется стандартный обработчик ссылок Windows. Журнал запуска: `var/v5/logs/launcher.log`.
- В Step 2 слева от `+ Add` появилась `Clear table` для каждого списка. С подтверждением переносит все активные и приостановленные строки выбранного списка в Trash, независимо от фильтров. История и результаты не удаляются. Очистка склада не останавливает мониторинг моделей. Во время проверки сначала нужен Hard stop.
- `Mode · cache` влияет только на возраст кеша: Quick 12 ч, Balanced 4 ч, Deep без кеша. Методы сбора одинаковые; защиту сайтов режим не отменяет.
- Если наличие не подтверждено, собранная цена всё равно видна в сводке с пометкой `reported price · availability unconfirmed` и ссылкой. Она не включается в Lowest in-stock.
- Сетевые ошибки отличены от CAPTCHA/Not found. При `Network connection failed` проверьте подключение/правила брандмауэра и запускайте EXE обычным двойным щелчком из папки, не из ограниченной среды тестирования.

## Запуск и сохранность v4

Запустите `PriceMonitor.exe` из папки `PriceMonitor-v5.0.0-windows-x64-portable`.
Интерфейс откроется по адресу http://127.0.0.1:8050. Если вкладка закрыта, откройте этот адрес снова.
Не переносите EXE отдельно от `_internal`. Windows x64, установка Python не требуется.
Закрытие вкладки не завершает локальный сервер. Для полного выхода перед обновлением завершите процесс PriceMonitor в Диспетчере задач (сверьте путь к папке v5).

v4 остаётся в своей старой папке и использует порт 8000. Данные v5 независимы:
`var/v5/catalog.sqlite3`, экспорт — `var/v5/exports`. Для резервной копии закройте приложение и скопируйте всю папку `var`.
Git-точка отката v4: тег `v4.2.4`. Исходный код v4 не изменён.

## Что изменилось

- Запросы только к Kaina24, Salidzini и Hinnavaatlus. Переходов сборщика к магазинам нет.
- Восемь магазинов — это фильтры продавцов в предложениях маркетплейсов. Их переключатели скрывают/показывают столбцы и не меняют общерыночные min/max.
- Min/max считаются среди всех захваченных продавцов каждого маркетплейса, а не только восьми выбранных магазинов.
- Считаются обычные цены товара с подтверждённым наличием. Рассрочка и доставка не прибавляются. Предзаказ идёт отдельно. Если наличие не подтверждено, цена видна в раскрытии и в столбце магазина с `Availability unknown`, но не попадает в in-stock min/max.
- Срок доставки на странице сам по себе не доказывает фактическое наличие.
- Колонка магазина показывает минимальную доступную in-stock цену; если таких нет — минимальную из остальных с явным указанием наличия в раскрытии. Там же все предложения, маркетплейс, время и ссылка на страницу сравнения.

## 1. Загрузка моделей

Достаточно импортировать сток XLSX/XLSM: B — название, C — количество, D — себестоимость. Строка с названием в B и пустыми C/D обозначает склад.
Распознанные модели автоматически добавляются в мониторинг. Одна модель на нескольких складах проверяется один раз на каждом включённом маркетплейсе.
Нулевой остаток и исчезновение строки из следующего файла не выключают мониторинг. Намеренно поставленные паузы и корзина сохраняются.
Неоднозначные названия остаются `Unmatched`: исправьте Linked model в Edit. Неоднозначные модели не угадываются.
Дополнительный файл моделей необязателен: листы TV/SB/Monitors, колонка Model. Можно добавлять вручную.
Поисковый запрос имеет вид `TCL + модель`.

## 2. Проверка

Включите нужные маркетплейсы и нажмите Start monitoring. На SKU — максимум три проверки вместо отдельных проверок магазинов.
Внутри каждой проверки могут понадобиться запрос выдачи, карточки сравнения и страниц списка продавцов.
Разные маркетплейсы проверяются параллельно, внутри каждого — последовательно с паузой 3 секунды.
Hard stop прекращает текущую работу и сохраняет полученные результаты. Кнопка ↻ у модели обновляет только её.
Предыдущий прогон открывается под таблицей; новые изменения каталога не добавляют строки в старые прогоны.

Режимы: Balanced — полный автоматический результат не старше 4 часов; Quick — до 12 часов; Deep — без кеша цен.
Ручные решения и отрицательные результаты не используются как новые автоматические подтверждения. Старые решения показаны с датой.
История хранится до очистки пользователем и не означает актуальную цену.

## 3. Защищённые страницы и ручная работа

`Action required` — CAPTCHA, неизвестная разметка или неполные данные. Это не `Not found`.
При защите автоматические обращения к этому маркетплейсу приостанавливаются на 10 минут; остальные площадки продолжают работать.
Ручной ввод доступен сразу, ждать cooldown не нужно. Проверку можно повторить кнопкой Capture again.

1. Open verification открывает маркетплейс. CAPTCHA проходите самостоятельно.
2. Можно вставить ссылку именно на страницу сравнения/выдачи маркетплейса. Ссылки Varle, RDE и прочих магазинов в v5 не принимаются.
3. Без расширения внесите цену, продавца и наличие вручную через Save manual price.
4. В раскрытии min/max кнопка Add seller offer / review добавляет остальных продавцов. Edit offer исправляет выбранное предложение; Remove false match удаляет ложное совпадение только из этого прогона.
5. После просмотра всех предложений отметьте `I reviewed all seller offers…`. До этого min/max помечены `partial`: это границы только внесённых предложений, а не всего рынка.
6. Mark not found применяется ко всему SKU на выбранном маркетплейсе, а не к одному продавцу.

`Not listed` у магазина означает, что он не указан на проверенных страницах маркетплейсов; это не доказательство отсутствия товара в самом магазине.
`Unverified` — площадки ещё не дали достаточно данных для вывода о магазине.
Жёлтая цена — отклонение от других собранных цен не менее чем на 20%, повод проверить модель; не автоматическое удаление.

## Необязательное расширение v5

Приложение работает без расширения: доступные HTML-страницы собираются автоматически, защищённые обрабатываются вручную.
Для захвата открытых после CAPTCHA страниц установите отдельное расширение v5:

1. Откройте `edge://extensions`, включите Developer mode.
2. Load unpacked → папка `edge-extension` рядом с новым EXE.
3. В расширении адрес `http://127.0.0.1:8050`. Проверьте соединение.

У v5 другой идентификатор расширения; v4 можно оставить установленным. Не подключайте старое расширение к v5.
Расширение v5 читает только три маркетплейса. Во вкладке захвата переходы за пределы выбранного маркетплейса блокируются.
Оно не решает CAPTCHA, не меняет IP и не обходит защиту.
Смена разметки сайта может потребовать ручного ввода. Live-проверка этой сборки подтвердила извлечение продавцов Hinnavaatlus; Kaina24/Salidzini закрыли автоматическое чтение защитой. После CAPTCHA корректность захвата этих двух сайтов надо проверить в вашей сессии.

## Excel

Export table to Excel: сводная таблица, все предложения продавцов и отдельный лист статусов проверок.
Печать — альбомная A4, одна страница по ширине, несколько по высоте при необходимости.
Excel допускает только одну ссылку на ячейку, поэтому отдельная кликабельная строка для каждого предложения находится на листе All seller offers.
